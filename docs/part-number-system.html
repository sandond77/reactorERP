Part Number System

How Reactor identifies a card: Part # (SKU) + set code + language. The naming convention that makes every Snivy from every set distinguishable.

The SKU format

{GAME}-{LANG}-{SETCODE}-{NUMBER}

PKMN-JP-SV11B-088   ← Snivy from Japanese Black Bolt #088
PKMN-EN-BS-006      ← Charizard from English Base Set #006
PKMN-JP-S12a-196    ← Green's Exploration from JP VSTAR Universe #196

Each segment narrows the identity:

  • GAME — PKMN for Pokemon (most inventory). Future games would get their own codes.
  • LANG — EN or JP. These same set codes often exist in both languages; language is part of the identity.
  • SETCODE — the canonical short code for the set (e.g. SV11B for Black Bolt, S12a for VSTAR Universe).
  • NUMBER — the card number within the set as printed.

How set codes resolve

Set codes are looked up from a shared list of known sets (EN_SETS + JP_SETS in the server). When you enter a card name like "2025 POKEMON JAPANESE SV11B-BLACK BOLT 088 SERVINE", Reactor:

  1. Tries to find a known set code as a substring.
  2. If found, picks the language that matches (JP for SV11B; some codes are EN-only).
  3. If the same code exists in both languages, prompts you to disambiguate (the Language Ambiguous modal during import).
  4. If no known code is found, prompts you to assign Game / Language / Set Code / Set Name (the Unlinked modal).

The card_catalog table

The catalog is a shared global table — not user-scoped. Once a card is in the catalog, every user benefits (and every user references the same canonical name + set + image).

New catalog entries get created automatically during import or manual entry when a card name + set combo isn't already present. You can curate the catalog directly via Manage → Parts.

card_name_override

The catalog stores short canonical names (e.g. "Shining Mew"). Individual card_instances can carry a card_name_override with the full imported name (e.g. "2001 Pokemon Japanese Promo Corocoro Comics 151 Shining Mew Holofoil"). Display logic shows the override when present, falling back to the catalog name.

This lets imports preserve full PSA labels and detailed names without polluting the shared catalog.

Why this matters

  • Multi-language inventory — same card in EN and JP are separate inventory items with separate cost basis and separate listings.
  • Cross-set lookups — searching "Shining Mew" finds every set and language it appears in.
  • Listings aggregation — the Listings page aggregates by SKU + grade + platform. Same SKU means same card.
