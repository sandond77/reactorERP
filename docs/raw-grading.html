Grading

Every grading submission you've sent out. Track shipping, processing, and returns.

What you see

One row per grading_submissions entry. Columns: Submission #, Company (PSA/BGS/CGC/...), Service level, Sub-batch ID, Status, Card count, Total cost, Shipped date, Expected return, Returned date.

Status flow: building → shipped → received_back → returned.

Common actions

  • + New Batch — open a new submission. Pick company + service level + per-card grading cost.
  • Click a row — opens the batch detail. See every card in it, edit the per-card grading cost, mark shipped/received, process returns.
  • Process Return — once cards come back, upload PSA/BGS's return CSV. Each cert becomes a graded slab with cost = raw_cost + grading_cost. See Grading Submission for the full flow.
  • Delete Batch — reverts a submission. Unsold/un-listed slabs are removed; source raw cards are restored from the audit log. Sold/listed slabs are kept and reported.

Tips

  • Edit grading_cost after the fact — fans out to every linked slab AND every historical sale's total_cost_basis. P&L stays accurate even when the grader corrects an invoice.
  • Sub-batch ID — PSA assigns this when they receive your package. Add it to the batch so the return matcher can use it for disambiguation.
  • Legacy slabs (pre-migration 056) don't have a grading_batch_id and won't auto-update if the batch cost changes.
