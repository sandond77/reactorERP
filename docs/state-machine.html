State Machine

Every card row has a status that moves through the lifecycle. State transitions are explicit — no implicit movement between stages.

The flow

purchased_raw → inspected → grading_submitted → graded → sold
                         → raw_for_sale → sold
                                       → lost_damaged (terminal)

State definitions

  • purchased_raw: just intaked, hasn't been inspected.
  • inspected: condition assigned, awaiting routing decision (sell raw or submit to grading).
  • raw_for_sale: routed to sell raw — listed or unlisted.
  • grading_submitted: routed to a grading company, awaiting return. Counts as in-flight inventory.
  • graded: came back from grading, now a slab. Has a slab_details row joined.
  • sold: revenue recorded. The matching sales row has the snapshotted cost basis.
  • lost_damaged: terminal write-off. Excluded from P&L going forward.

Lot traceability

Every card traces back to a purchase_id (format: RP-YYYY-NNN). This is the lot-level key. A raw bulk lot's purchase_id follows that card through inspection, grading, and final sale — including onto the slab's cost basis as raw_cost.

So when you ask "what did I pay for this PSA 10 cert?", the answer is:

total_cost_basis = raw_cost (from lot RP-2025-B1) + grading_cost (from submission #...)
