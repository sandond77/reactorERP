Location System

How physical storage maps to the data model. Hierarchical, typed, and able to flag card show inventory automatically.

The model

A location is a tree node with these properties:

  • Name — human-friendly label ("Slab Binder A", "Office Shelf 2", "Card Show Table").
  • Type — graded, raw, or both. Restricts which cards can be assigned. The slab modal only offers graded + both locations; the raw modal only offers raw + both.
  • Parent — optional. Makes the location a child of another (e.g. "Office Shelf 2" parented under "Office").
  • is_card_show — boolean. Locations flagged here behave specially (see below).

Card_instances reference a location via location_id. The slab/raw detail modals expose the Location dropdown for assignment.

The Card Show side-effect

When you assign a card to a location with is_card_show = true, the card's own is_card_show flag flips to true and card_show_added_at is stamped. This is how cards "go on the show table" automatically — you just move them to the show location.

Conversely, removing a card from a card-show location (or assigning it elsewhere) clears the on-show flag.

This means you can structure your physical workflow as: "Move the binder to the Show location" → cards auto-flag for the show. Move it back → flag clears.

Why typed locations matter

  • Avoids misclicks — you can't accidentally assign a slab to a raw-only location.
  • Surfaces structure — the dropdown only shows valid options for that card.
  • Inventory audits — when reconciling a binder, you scope by location and only get the right card type.

Hierarchies in practice

Office (both)
├─ Slab Binder A (graded)
├─ Slab Binder B (graded)
├─ Raw Box 1 (raw)
└─ Raw Box 2 (raw)

Card Show Table (both, is_card_show=true)
├─ Show Slab Display (graded)
└─ Show Raw Bin (raw)

Nesting is one level deep for assignment purposes — cards reference the leaf node directly, not the parent. The parent exists for grouping in the UI.

Deletion + reassignment

A location can only be deleted if no cards reference it. If you want to retire a location, first reassign all its cards (or leave them with location_id = null).

Tips

  • Don't over-nest — flat structures are easier to navigate. "Slab Binder A" works better than "Office → Cabinet → Top Shelf → Slab Binder A".
  • One Card Show location per show isn't necessary — most users have one "Card Show Table" and use it for whatever show is current. The show identity is tracked separately on each sale.
