Inventory Audit

Physical-vs-system reconciliation. Walk your binders / boxes, mark what's actually there, surface discrepancies.

The flow

  1. Start an audit. Pick a scope (entire inventory, by location, by purchase lot, by date range).
  2. Reactor generates the expected list — every card_instance in scope, with its current location.
  3. Walk the physical inventory. For each card you find, mark it confirmed. The UI accepts cert # scans or manual ticks.
  4. Submit. Reactor diffs confirmed vs expected and flags:
    • Missing — expected but not confirmed. Possibly lost or misfiled.
    • Found unexpected — confirmed but not in scope. Possibly wrong location, or a card you forgot to log.
    • Match — everything reconciled.

Resolving discrepancies

For each flagged item:

  • Misfiled? Update its location.
  • Genuinely lost? Set status to lost_damaged.
  • Found but not logged? Create the card_instance retroactively (you'll need to assign a cost basis manually).

Tips

  • Smaller scopes (one binder) are easier to reconcile than full-inventory audits.
  • Audit findings are written to the audit log as a special inventory_audit event so you can trace decisions later.
  • For grading-in-flight cards, the system knows they're "expected absent" — won't flag them as missing.
