CSV Import

Bringing existing inventory or transaction history into Reactor. Four import types; pick the one that matches what your CSV represents.

How the import works

  1. Upload your CSV or Excel (.xlsx, .xls). Any format, any columns.
  2. AI detects the import type and proposes a column mapping. Confidence shown next to the detected type.
  3. Review the mapping. The Field Reference sidebar explains every target field. Unmapped columns are skipped.
  4. Confirm. Reactor processes the file. Ambiguous rows (e.g. set codes that could be EN or JP) trigger modal prompts.
  5. Import History at the bottom tracks every import you've done, with row counts and error counts.

The four import types

Graded Cards

You have slabs already. Each row = one slab.

  • Required card_name, cert_number, grade
  • Recommended company, grading_cost, purchase_cost, purchased_at, sale_price, sold_at, platform, platform_fees, shipping_cost

If you include sale columns, the row creates a sold slab. If you don't, it creates an unsold slab in inventory.

Raw Purchases

A history of orders. Each row = one order.

  • Required cost, purchased_at
  • Recommended type, card_name, set_name, card_number, language, quantity, source, order_number

type=raw rows auto-create a matching card_instance in inventory. type=bulk rows stay as orders pending intake — you'll split them during inspection.

Bulk Sales

A flat list of completed sales matching existing inventory.

  • Required identifier (cert # for graded, or purchase ID like RP-2025-001 for raw), sale_price
  • Recommended platform, platform_fees, shipping_cost, sold_at, currency, unique_id

Each row finds the existing card by identifier and records a sale.

Expenses

Supplies, postage, subscriptions — anything that hits P&L outside of cost basis.

  • Required description, amount, date
  • Recommended type, currency, order_number, link

Common problems

  • "Unlinked rows" — Reactor couldn't find a known set code for one or more rows. A modal prompts you to assign Game, Language, Set Code, and Set Name. Required to proceed.
  • "Language ambiguous" — set codes that exist in both EN and JP (e.g. some Sword & Shield codes) need disambiguation. Modal prompts per ambiguous row.
  • Bulk sale "no inventory found" — the identifier doesn't match an existing slab or raw purchase. Common causes: cert # has leading zeros, purchase ID is wrong format, the card was already sold.
  • Costs look wrong after import — for raw purchases, cost is the total order cost; per-card is computed from cost / quantity.
