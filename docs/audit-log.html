Audit Log

Every state-changing event in the system, in chronological order. Created, updated, deleted, transformed.

What you see

One row per audit_log entry. Columns: Timestamp, Actor (user or agent), Entity type (card_instance, sales, listings, etc), Entity ID, Action (created / updated / deleted / restored), Before / After (diff).

Click any row to see the full before/after JSON of the changed record.

Filters

  • Entity type — card_instances, sales, listings, raw_purchases, grading_submissions, etc.
  • Action — created, updated, deleted, restored.
  • Date range — when the change happened.
  • Actor — user or AI agent.
  • Entity ID — search by specific card or sale ID.

Why it matters

  • Reverts — deleting a grading batch restores raw cards from this log. Same for sale deletes.
  • Investigation — when a number looks wrong, the audit log shows when it changed and what it changed to.
  • Trust — no soft-delete fields; the log is the source of truth for "did this card ever exist?"

Tips

  • Audit entries aren't editable. If a log shows something incorrect, the only fix is to write a new state-changing event.
  • The agent's actions are tagged with actor = AI so you can distinguish them from your own.
