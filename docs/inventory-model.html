Inventory Model

Reactor distinguishes two fundamentally different ways inventory exists, and they behave differently throughout the system.

Raw cards — quantity-based

A raw card record is a lot: grouped by purchase + condition, with a quantity field. One row can represent 24 NM cards from the same bulk lot.

  • Stored in card_instances with purchase_type = 'raw'
  • Quantities are split out from the bulk lot during inspection
  • Each split row gets its own decision: sell raw or submit to grading
  • Cost basis is allocated proportionally across splits

You can have multiple raw rows for the same SKU at different conditions — Reactor doesn't collapse them.

Graded slabs — item-based

A graded slab is one physical card: cert #, grade, grading company, cost basis. Always quantity = 1.

  • Stored in card_instances with purchase_type = 'pre_graded' (or transformed from raw via grading)
  • Joined 1:1 to slab_details (cert number, grade, label, company)
  • Cost basis = raw cost (if it came from a raw lot) + grading cost

Never flattened into a quantity-based model. A 5-card eBay set listing is 5 separate card_instances rows linked by a shared listing_group_id.

What this means for users

  • Don't try to track raw cards as individual items. They're lots until you split them during inspection.
  • Don't try to track slabs as a quantity. Each cert is its own row, period.
  • The state machine is enforced. The UI won't let you skip a state; the agent won't either.
  • Cost basis is real money, not an estimate. If something doesn't reconcile, that's a bug, not a rounding error.
