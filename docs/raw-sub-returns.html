Sub Returns

Process the CSV when grading returns. Each cert becomes a graded slab; non-graded outcomes (lost, not_submitted, not_graded) take their own paths.

The flow

  1. Pick the batch. Sub Returns lists every submission with status shipped or received_back.
  2. Upload the CSV. PSA, BGS, CGC each have slightly different formats; Reactor parses them.
  3. Match. A scoring matcher pairs each CSV row to a batch item using card name, card number (from PSA's Description column), set tokens, year, language, and line position. Each match has a confidence: Strong / Good / Weak / Manual.
  4. Review slots. Each batch slot is editable: card name, cert #, grade, label. CSV-imported values are locked (🔒) by default — click to unlock for override.
  5. Set dispositions. Per slot:
    • graded (default) — creates a new slab. Cost = raw_cost + grading_cost.
    • not_graded — came back ungraded. Creates a new raw card_instance with cost = raw_cost + grading_cost.
    • lost — write-off. No new row.
    • not_submitted — wasn't actually sent. Creates a new raw card_instance with cost = raw_cost (no grading fee).
  6. Confirm. Slabs + raw rows are created; source raw quantities decrement; batch is marked returned.

Remap if matching is wrong

The Remap column on each slot lets you reassign which batch item it maps to without re-uploading. Useful when the matcher is confident-but-wrong.

Qty mismatch

If the CSV has fewer rows than the batch's expected cards (some never shipped, some came back partially), use the per-row Ignore (×) button to drop a slot from the payload. The source raw row stays in grading_submitted for a future return.
